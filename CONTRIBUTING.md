# Contributing to SlideLite

Thanks for helping make SlideLite better. SlideLite is a **viewer**: contributions that
add editing, cloud features, accounts or telemetry are out of scope. Fidelity,
reliability and performance improvements are very welcome.

## Getting started

```bash
sudo apt install python3-gi gir1.2-gtk-3.0 gir1.2-webkit2-4.1 python3-venv nodejs
make venv && . .venv/bin/activate
./bin/slidelite docs/showcase.pptx
```

`SLIDELITE_DEBUG=1 ./bin/slidelite deck.pptx` enables the WebKit inspector
(right-click → *Inspect Element*) and logs messages between the page and the host.
`make dev FILE=deck.pptx` serves the same UI on `http://127.0.0.1:8765` for debugging
in a regular browser.

## Project layout

| Path | What lives there |
|---|---|
| `slidelite/presentation/` | OOXML engine: zip/OPC access, safe XML, themes, colours, fonts, preset geometry, masters/layouts/slides, timing, metafiles, table styles. Pure Python, no GUI imports. |
| `slidelite/render/` | Model → HTML/SVG: shapes, text, paint (fills, lines, effects), tables, charts, SmartArt. |
| `slidelite/server/` | In-memory router and the per-document session (slide, media and image endpoints). |
| `slidelite/app/` | GTK application, window, hardened WebKit view. |
| `slidelite/web/` | Viewer UI (ES modules): viewer, thumbnails, slide show, transitions, animations. |
| `slidelite/settings.py`, `recent.py` | Local preferences and recent files. |
| `packaging/` | `.deb` build script, desktop entry, AppStream metainfo, man page. |
| `tools/` | Fixture and showcase generators, screenshot tool, preset compiler. |
| `tests/` | pytest suite (`tests/js/` holds the Node unit tests). |

## Tests

```bash
make test        # all Python tests; GUI tests run when a display is available
make test-js     # node --test unit tests for the UI helpers
make lint        # ruff check + format check
```

- **Fixtures** in `tests/fixtures/` are synthetic and generated by
  `tools/make_fixtures.py` (requires python-pptx): `make fixtures`. Never commit
  real-world presentations.
- **Rendering regression tests** compare rendered markup with snapshots in
  `tests/golden/`. After an intentional rendering change, review and update them with
  `SLIDELITE_UPDATE_GOLDEN=1 python -m pytest tests/test_golden.py`, and include the
  snapshot diff in your commit.
- **Crash tests** fuzz the fixtures. Run a longer campaign with
  `SLIDELITE_FUZZ_ITERATIONS=500 python -m pytest tests/test_robustness.py`.
- GUI tests drive the real WebKit view through `tests/harness.py`. They use a throwaway
  settings profile, so your own settings and recent files are never touched.

## Guidelines

- Treat every presentation as hostile: parse through `xmlsafe`, read parts through
  `opc.Package`, escape all text with `render.markup.esc`, and never let one bad shape
  break a slide (render errors are caught per shape).
- No network access, ever. New UI resources must be served from the bundled `web/`
  directory.
- Keep the UI uncluttered. *Open → View → Present.*
- Match the surrounding code style; `ruff format` is the source of truth for Python.

## Commits

Use small, focused commits with conventional prefixes:

```
feat: render pattern fills on table cells
fix: keep bullet colour when the run colour is a scheme colour
perf: cache converted metafiles per document
test: add golden snapshot for vertical text
docs: document the --presentation flag
```

Before committing, run `make lint test test-js`.

## Releasing

1. Bump `__version__` in `slidelite/__init__.py` and add a `<release>` entry to
   `packaging/io.github.ammarqaisar.SlideLite.metainfo.xml` and `CHANGELOG.md`.
2. Commit, then tag and push: `git tag v1.2.3 && git push origin v1.2.3`.
3. The release workflow runs the tests, builds the `.deb` and publishes the GitHub
   Release.
